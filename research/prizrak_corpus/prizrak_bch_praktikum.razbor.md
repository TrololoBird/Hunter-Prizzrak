## 1. МЕТОД пошагово (главная ценность практикума)

Порядок «нырнуть вниз чтобы найти → вернуться наверх чтобы торговать»:

1. **HTF первым: недельный/месячный, весь график на один экран.** Первый взгляд ДО профилей: в
   большой ли структуре актив? (BCH — в большой сужающейся структуре). Отметить: большой уровень
   слома/стоповый, ловушки, очевидные зоны интереса «даже издалека».
2. **★ ПРОВЕРИТЬ, ПОЛНЫЙ ЛИ ГРАФИК** (ключевой шаг, которого нет в PDF). Фьюч BCH начинается
   дек-2019 → переключиться на **СПОТ `BCH/USD` с провайдером CRYPTO** (самый полный). Найти историю
   НИЖЕ видимого лоя: поставить луч на нижний лой, нырнуть на мелкий ТФ, увидеть что ниже. Нашёл
   **ATL ~73, уровень ~80, зона от ~82, mid ~76** → пометил зону 70–83. **Не строить сетапы на
   неполном графике.**
3. **VRVP не работает на крипто-споте** (нет объёма) → оценивать визуально. На фьюче — **Фиксированный
   профиль объёма, натянутый на ВСЕ свечи структуры** (первичен); общий профиль — вторичен.
4. **RSI (недельный/4ч)** — перепроданность, потенциал перелоя/конвера, слом трендовой + дивер как
   аргумент удержания/входа (доп-факторы).
5. **Строить КАЖДЫЙ сетап**: якорь на HTF-уровень/ПОК → нырок на LTF за точными уровнями и за тем,
   **что ещё не тестировали**. Цвета: **бордовый/жирный = основной**, **жёлтый = вспомогательный/
   снайпер/high-risk**, **зелёный = закуп/спот-зона**. Видимость уровня «на всех интервалах» (основной)
   или «текущий и ниже» (локальный).

## 2. Принципы (refinement-слой — то, чего PDF-база не проговаривает)

- **НЕТ единственно верного сетапа** (дословно): отличаются округлением уровней, группировкой зон,
  **агрессией** (10% агрессивный / 15% консервативный), шириной (широкий-защитный / узкий / разбитый
  на 2). Цель — СВОЙ понятный сетап под свой РМ/стиль.
- **Один актив → НЕСКОЛЬКО параллельных сетапов по горизонту/агрессии** (не конкурирующие кандидаты, а
  разные трейд-планы): локальный · шорт-от-недельного · снайпер-на-перелой · спот. См. §3.
- **ПОК — неигнорируемый якорь**: «POC в любом случае не проигнорируешь»; **закуп НИЖЕ ПОК — сомнителен**.
- **«База в базе»**: под-структура со своим ПОК/зоной ВЫШЕ основной → **расширяем зону интереса** до неё.
- **Уровни/зоны СМЕЩАЮТСЯ по ТФ**: объёмную зону смотреть на недельке+месяце+дневке; якорь — на родном
  ТФ структуры, но учитывать все («нужна позиция, а не ювелирность»).
- **★ «С СЕРЕДИНЫ БАЗЫ не вхожу»** — даже на конверах; из середины входят только те, кто уже в позиции
  (добор). Середина = буфер между двумя более чёткими сетапами. **← прямой сигнал для кода (§4).**
- **Снайпер-уровни = НЕтестированные уровни**, найденные глубоким нырком + отматыванием (что цена
  «никогда не забирала»); в комплекте — **ХАИ** (цена может вернуться тестировать истинный уровень
  переприора). High-risk, быстрый RR 1:2–1:3, жёлтый, по факту/low-risk/сетки.
- **База переприор**: вся база = уровень смены приоритета (её границы); ювелирный тест + отработка →
  свежей реакции не ждём, но «проходная реакция» возможна.
- **Распределение закупа (спот)**: интервал ≥25–30%; риск 3-закупов → **срезать все на ~30%, треть
  держать в загашнике**, добирать только на подтверждённом развороте (конвера на недельке + структура).
- **Управление**: стоп **15% макс** (агрессив 10%); торговать зоны раздельно, стоп в дальней зоне →
  по приходу перезаход, стоп выше, добор; **трейл вверх**.

## 4. Cause→effect → работа по коду (`hunt_core/prizrak`) — где КОД НЕ совпадает с методом (видео=истина)

0. **★ ГЛАВНОЕ (измерено на BCH): лонг якорится на ВЕРХ бокса, а не на ПОК.** Автор берёт лонг от
   **ПОК внизу структуры (196)**; наш `compute_interest_zones` для широкого/straddle-бокса даёт лонг-край
   = `hi` (верх, 218 — у цены), ПОК/низ не всплывает как вход. → лонг-вход должен якориться на **ПОК
   зоны** (как `_forward_zone_candidate` уже делает через `_poc_entry`), а не на верхнюю границу бокса;
   для широкого бокса (>4%) показывать ПОК-уровень, а не край у цены. Это прямое несоответствие методу.
1. **«Один актив → N сетапов по горизонту» = наши setup_kind, но подавать ПАРАЛЛЕЛЬНО.** Сейчас
   `build_prizrak_signals` возвращает кандидатов и берётся сильнейший (top-1/dedup). Автор же держит
   ВСЕ 4 как разные планы (local=zone/forward · weekly-short=forward-short HTF · sniper=zone_target_deep ·
   spot=spot_ladder). → доставка должна показывать до нескольких сетапов, помеченных **горизонтом/
   агрессией**, а не один «сильнейший». (Связано с упрощением TG-формата — user ask.)
2. **★ «С середины базы не вхожу» — проверить, что forward/zone-кандидат НЕ эмитит из середины зоны.**
   `_zone_candidate` уже имеет «don't trade the middle» гейт (orchestrator ~1348). Убедиться, что он
   реально режет вход, когда цена в середине объёмной базы (BCH mid 215–225 — WAIT, не сигнал).
3. **Проверка полноты графика / история ниже видимого лоя + ATL.** Автор явно тянет СПОТ-историю ниже
   фьюч-старта, чтобы найти ATL/глубокие уровни для спот-сетапа. У нас spot_ladder есть — но берём ли
   мы достаточную ИСТОРИЮ и ATL? Флаг: спот-сетап должен якориться на реальный ATL + под-лоевые уровни,
   не только на fetch-окно.
4. **«База в базе» → расширение зоны интереса вверх.** Под-структура со своим ПОК выше основной
   расширяет зону закупа. Наш accumulation-движок находит отдельные боксы, но «расширить зону до под-
   структуры выше» — отдельная логика. Флаг.
5. **ПОК — неигнорируемый якорь; ниже-ПОК вход сомнителен.** `_poc_entry` уже якорит на ПОК. Правило
   «не ставить закуп ниже ПОК» — проверить, что глубокий deep-кандидат не уходит СИЛЬНО ниже ПОК без
   пометки «сомнительно/по факту».
6. **Снайпер = нетестированные уровни + хаи.** deep-кандидат должен предпочитать уровни, которые цена
   «никогда не забирала» (untested), и включать возвратные ХАИ. Наш `_level_already_worked` считает
   отработку — «untested» это обратное; можно ранжировать snайпер-зоны по НЕ-тестированности.
7. **Мультибокс-подача снайпера/спота (жёлтый high-risk) отдельным tier'ом** — «по факту / low-risk /
   сетки», быстрый RR 1:2–1:3, а не как основной сигнал.
