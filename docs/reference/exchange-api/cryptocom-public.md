# Crypto.com Exchange — публичный API (справочник оракула)

> **Статус: СПРАВОЧНИК** (собрано 2026-07-31 из ОНЛАЙН-документации).
> Только ПУБЛИЧНЫЕ эндпойнты — ни одного, требующего ключа, подписи или аккаунта.

## Зачем этот файл

Crypto.com здесь — **независимый оракул** (`.claude/skills/live-verify/SKILL.md`). Ценность
именно в чужеродности: другая биржа, другой код, **не CCXT и не наш движок**, поэтому расхождение
ловит дефект в НАШЕМ транспорте, который «живые данные с того же Binance» поймать не могут по
построению.

До сегодняшнего дня у оракула **не было ни строки офлайн-документации**: он был доступен только
через MCP-инструменты, чьи параметры приходилось угадывать. Скилл при этом прямо предупреждает
«список сверять `get_instruments`, не угадывать» — а сверять было нечем.

⚠️ **Grep по `hunt_core/` (2026-07-31): ноль упоминаний Crypto.com.** Оракул живёт целиком вне
кода — это MCP-инструменты, которые дёргает агент по скиллу. Значит все «✅ ИСПОЛЬЗУЕТСЯ» ниже
означают «используется агентом через MCP», а не «есть вызов в проде».

## 1. Транспорт: базовые URL и конверт

| Что | Production | UAT / sandbox |
|---|---|---|
| REST v1 | `https://api.crypto.com/exchange/v1/{method}` | `https://uat-api.3ona.co/exchange/v1` |
| WS market data (публичный) | `wss://stream.crypto.com/exchange/v1/market` | `wss://uat-stream.3ona.co/exchange/v1/market` |
| WS user (➖ приватный, вне scope) | `wss://stream.crypto.com/exchange/v1/user` | `wss://uat-stream.3ona.co/exchange/v1/user` |
| Announcements (иной корень!) | `https://api.crypto.com/v1/public/get-announcements` | — |
| Легаси v2 | `https://api.crypto.com/v2` | ➖ устарело, не использовать |
| Легаси derivatives | `https://deriv-api.crypto.com/v1` | ➖ слито в `exchange/v1` |

**Публичные методы вызываются GET'ом с query-параметрами.** Приватные — POST с телом и подписью
(вне scope). REST и WS используют **один и тот же формат запроса/ответа** — это заявлено в
официальном введении и полезно: WS-канал и REST-метод возвращают одинаковые поля.

Конверт ответа:

```json
{ "id": 1, "method": "public/get-candlestick", "code": 0, "result": { ... } }
```

| Поле | Тип | Смысл |
|---|---|---|
| `id` | long | идентификатор запроса (0 … 2⁶³−1); в WS-ответе эхо запроса |
| `method` | string | имя метода (`public/...`) |
| `code` | number | **0 = успех**; ненулевое — ошибка |
| `result` | object | полезная нагрузка |
| `message` | string | текст ошибки (опционально) |
| `nonce` | number | текущее время в **миллисекундах** |

⚠️ **`code == 0` — это не HTTP-статус.** Ответ может прийти `HTTP 200` с `code != 0`. Проверять
надо `code`, иначе получим ровно тот класс дефекта, который в проекте зовётся I-6: правдоподобное
число на месте отсутствующих данных.

## 2. КРИТИЧНОЕ ДЛЯ ОРАКУЛА: именование инструментов

Скилл предупреждает не угадывать имена — вот почему.

| Тип | Шаблон | Пример Crypto.com | Наш эквивалент |
|---|---|---|---|
| Спот | `BASE_QUOTE` (подчёркивание) | `BTC_USD`, `BTC_USDT`, `ETH_BTC` | `BTC/USDT` (ccxt spot) |
| Бессрочный своп | `BASEQUOTE-PERP` (без разделителя, дефис) | `BTCUSD-PERP`, `ETHUSD-PERP` | `BTC/USDT:USDT` |
| Фьючерс с экспирацией | `BASEQUOTE-{expiry}` | `ETHUSD-210528`, `BTCUSD-241227` | ➖ у нас нет |
| Индекс | `BASEQUOTE-INDEX` | `BTCUSD-INDEX` | ➖ у нас нет |

`inst_type` (enum): `SPOT`, `PERPETUAL_SWAP`, `FUTURE` (в ответах также встречается
`CCY_PAIR` для спота — читать поле, а не выводить из имени).

### ⚠️ Три ловушки соответствия, каждая молча портит сверку

1. **Квота не совпадает: у нас USDT-перп, у них USD-перп.** `BTC/USDT:USDT` (Binance, маржа USDT)
   ↔ `BTCUSD-PERP` (Crypto.com, котировка USD). Это **не одна и та же бумага**: расхождение
   USDT/USD плюс разный фандинг дают законную базисную разницу. Порог из скилла (0.5% на
   ликвидном мажоре) это переживает, но интерпретировать разницу как «наш баг» нельзя, пока не
   вычтен базис. Для мажоров разница обычно единицы б.п.; на альтах — что угодно.
2. **Тот же тикер живёт в спот- и в перп-виде.** `BTC_USDT` (спот) и `BTCUSD-PERP` (перп) —
   разные цены. Наш движок мерит **перп**, значит сверять надо с `-PERP`, а не со спотом. Ошибка
   такого рода не выглядит ошибкой: обе цены правдоподобны.
3. **Не все наши символы у оракула есть вообще.** Universe Binance USDⓈ-M ≫ листинг Crypto.com.
   Отсутствие инструмента — это «сверить нечем», а не «расхождение 100%». Возвращать `None`, а
   не число (I-6).

### Как строить соответствие (единственный правильный способ)

`public/get-instruments` → таблица `symbol` × `base_ccy` × `quote_ccy` × `inst_type`. Ищем
строку, у которой `base_ccy == наш base`, `inst_type == PERPETUAL_SWAP`. Список стабилен —
скилл верно советует снимать его один раз за сессию.

Через CCXT то же самое даётся даром: **`market['id']` у `cryptocom` — это ровно строка
`symbol` из `get-instruments`**, потому что `parse_market` кладёт её в `id` без преобразований.
То есть `ccxt.cryptocom().market('BTC/USD:USD')['id']` даёт `'BTCUSD-PERP'` — готовый маппер,
не требующий собственной таблицы.

## 3. КРИТИЧНОЕ ДЛЯ ОРАКУЛА: время, единицы и границы бара

Сверка кадров бесполезна, если единица или граница бара разъезжаются. Проект уже ловил на этом
сдвиг локальных часов на 43.4 с (форминг-бар отдавался как закрытый 72% времени).

| Вопрос | Ответ Crypto.com | Наш контекст |
|---|---|---|
| Единица всех `t` / `start_ts` / `end_ts` | **миллисекунды** Unix epoch | совпадает с ccxt/Binance — ✅ единица одна |
| `create_time_ns` | наносекунды | ➖ только приватные ордера |
| Что означает `t` у свечи | **время НАЧАЛА (открытия) бара** | совпадает с Binance `openTime` |
| Граница недели (`7D`) | понедельник, UTC | совпадает с Binance |
| Граница `1M` | календарный месяц | совпадает |
| `nonce` в конверте | серверное время, мс | **дешёвый замер расхождения часов**: `nonce − наш_now` |

⚠️ **`nonce` — бесплатный независимый источник серверного времени.** Он приходит в КАЖДОМ ответе.
Это второй свидетель против сдвига локальных часов, и он не стоит ни одного лишнего запроса.

⚠️ **Не документировано и потому подлежит ЗАМЕРУ: отдаёт ли `get-candlestick` форминг-бар.**
Официальная страница про это молчит. Для инварианта I-5 («детекторы видят только ЗАКРЫТЫЕ бары»)
это решающий вопрос: если оракул отдаёт форминг, а мы — нет, сверка «последнего бара» сравнит
разные вещи и покажет фантомное расхождение. Проверять так: взять `t` последнего элемента и
сравнить с `floor(nonce / tf_ms) * tf_ms`. Равно → последний элемент ФОРМИНГ, брать `[-2]`.
Меньше на один шаг → последний ЗАКРЫТ, брать `[-1]`. **Замер, а не предположение** — и не
переносить вывод между таймфреймами без повторной проверки.

### Enum таймфреймов

Документированные значения `timeframe`: `1m`, `5m`, `15m`, `30m`, `1h`, `2h`, `4h`, `12h`,
`1D`, `7D`, `14D`, `1M`. Легаси-алиасы принимаются: `M1`, `M5`, `M15`, `M30`, `H1`, `H2`, `H4`,
`H12`, `D1`. Дефолт при отсутствии параметра — `M1` (одна минута).

⚠️ **Карта CCXT расходится с enum документации в обе стороны** (`ccxt 4.5.68`,
`ccxt.cryptocom().timeframes`):

| | документация | ccxt `timeframes` |
|---|---|---|
| `2h` | есть | **НЕТ** |
| `6h` | **НЕТ** | есть (`'6h': '6h'`) |
| остальные | `1m 5m 15m 30m 1h 4h 12h 1D 7D 14D 1M` | те же (`1d→1D`, `1w→7D`, `2w→14D`) |

То есть `6h` через ccxt может молча вернуть не то, что просили (или пустоту), а `2h` через ccxt
недоступен, хотя биржа его отдаёт. **Наш рабочий таймфрейм 15m есть в обоих списках** — для
основной сверки это неважно, но при выходе за 15m/1h enum надо перепроверять на живом ответе.

## 4. Публичные REST-эндпойнты

Колонка «лимит» — документированный лимит на метод (Crypto.com указывает их **поштучно**, а не
одним общим правилом). Значения сверены с весами, зашитыми в `ccxt.cryptocom().api` (`rateLimit`
= 10 мс на единицу веса): вес 1 → 100 запросов/с, вес 2 → 50/с, вес 3.33 → 30/с. Совпадение
двух независимых источников — вот основание, а не «разумное значение».

| Метод | Лимит | Статус | Что даёт |
|---|---|---|---|
| `public/get-instruments` | **30 req/s** (вес 3.33) | ✅ ИСПОЛЬЗУЕТСЯ — MCP `get_instruments`, шаг 1 скилла `live-verify` | справочник инструментов = единственный законный маппер имён |
| `public/get-book` | **100 req/s** | ✅ ИСПОЛЬЗУЕТСЯ — MCP `get_book`; сверка стакана/стен/`imb_*` | bids/asks с числом ордеров на уровне |
| `public/get-candlestick` | **100 req/s** | ✅ ИСПОЛЬЗУЕТСЯ — MCP `get_candlestick`; сверка кадров, I-5, свой профиль под ПОК | OHLCV |
| `public/get-tickers` | **100 req/s** | ✅ ИСПОЛЬЗУЕТСЯ — MCP `get_ticker` / `get_tickers`; сверка цены и свежести | last/bid/ask/24h/OI одним запросом |
| `public/get-trades` | **100 req/s** | ⬜ НЕ ПОДКЛЮЧЕНО (MCP-инструмент есть, скилл не использует) | лента сделок со стороной — независимая сверка тейкер-флоу и объёма |
| `public/get-valuations` | **100 req/s** | ✅ частично — MCP `get_mark_price` / `get_index_price`; ⬜ `funding_hist` / `funding_rate` / `estimated_funding_rate` не подключены | mark, index, фандинг (см. §4.6) |
| `public/get-expired-settlement-price` | **30 req/s** (вес 3.33) | ➖ не нужно — у нас нет срочных фьючерсов, только перпы | цена расчёта истёкших фьючерсов |
| `public/get-insurance` | **100 req/s** | ⬜ НЕ ПОДКЛЮЧЕНО | баланс страхового фонда — прокси стресса деривативов на бирже |
| `public/get-risk-parameters` | **100 req/s** (вес 1) | ⬜ НЕ ПОДКЛЮЧЕНО | параметры риска площадки: плечи по типам продукта, дисконты обеспечения |
| `public/get-announcements` | **100 req/s** (вес 1) | ⬜ НЕ ПОДКЛЮЧЕНО | делистинги, техработы, приостановки — **объясняют «дыру» в данных, не являясь ею** |
| `public/staking/get-conversion-rate` | **50 req/s** (вес 2, POST) | ➖ не нужно — ликвид-стейкинг, к сигналам отношения не имеет | курс конверсии стейкинг-токена |
| `public/auth` | 30 req/s | ➖ **ИСКЛЮЧЕНО** — точка входа под ключ, вне scope | — |

### 4.1 `public/get-instruments`

Параметров нет. Возвращает `result.data[]`:

| Поле | Тип | Смысл |
|---|---|---|
| `symbol` | string | **имя инструмента** — то, что подставляется в `instrument_name` везде (`BTCUSD-PERP`) |
| `inst_type` | string | `SPOT` / `PERPETUAL_SWAP` / `FUTURE` |
| `display_name` | string | человекочитаемое имя |
| `base_ccy` | string | базовая валюта — **по ней матчим наш символ** |
| `quote_ccy` | string | котируемая валюта (у перпов обычно `USD`, см. ловушку №1) |
| `quote_decimals` | number | знаков после запятой в цене |
| `quantity_decimals` | number | знаков в количестве |
| `price_tick_size` | string | **шаг цены** — прямой аналог нашего `market/tick_registry.py` |
| `qty_tick_size` | string | шаг количества |
| `max_leverage` | string | максимальное плечо |
| `tradable` | boolean | торгуется ли сейчас |
| `expiry_timestamp_ms` | number | экспирация, мс (у перпов отсутствует/0) |
| `underlying_symbol` | string | базовый инструмент (для деривативов — индекс) |
| `product_type` | string | `DIGITAL_CURRENCIES`, `COMMODITIES`, `EQUITY`, … |

⚠️ `price_tick_size` даёт **вторую, независимую** оценку шага цены. Проект уже имеет
`deliver/_labels.py`, который печатает уровни с сабтиковыми знаками, и `tick_registry.py`,
который эти шаги берёт из Binance. Сверять шаг оракулом можно только там, где инструмент
действительно один и тот же, и помня, что шаг у разных бирж законно различается.

### 4.2 `public/get-book`

| Параметр | Тип | Обяз. | Дефолт | Предел |
|---|---|---|---|---|
| `instrument_name` | string | **да** | — | `BTCUSD-PERP` |
| `depth` | string | **да** | — | **макс. 50** |

Ответ: `instrument_name`, `depth`, `bids[]`, `asks[]`, где элемент — **тройка
`[price, quantity, num_orders]`**.

⚠️ **Третий элемент — число ордеров, не накопленный объём.** Формат отличается от Binance
(`[price, qty]`). Код, который считает элемент `[2]` объёмом, получит правдоподобную чушь.

⚠️ **Потолок 50 уровней жёсткий.** Наши стены и `book_imbalance_1pct` считаются на нашей
глубине; если на мажоре 50 уровней не покрывают ±1%, сверка дисбаланса сравнивает **разные
окна**, а не разные биржи. Проверять покрытие диапазона прежде, чем объявлять расхождение
знака (ровно тот класс, что I-7: «окно 300 с при кэше в 1000 сделок — это не окно 300 с»).

### 4.3 `public/get-candlestick`

| Параметр | Тип | Обяз. | Дефолт |
|---|---|---|---|
| `instrument_name` | string | **да** | — |
| `timeframe` | string | нет | `M1` |
| `count` | number | нет | **25** |
| `start_ts` | number (мс) | нет | сутки назад |
| `end_ts` | number (мс) | нет | сейчас |

Ответ: `instrument_name`, `interval`, `data[]` с полями **`t` (начало бара, мс), `o`, `h`, `l`,
`c`, `v`**.

⚠️ **Дефолт `count = 25`.** Для профиля объёма под сверку ПОК этого мало на порядки: бимодальность
ПОК в этом проекте вскрылась только на разрешении 4785 баров. Не запросив `count` явно, получим
профиль по 25 барам и «расхождение», которого нет.

### 4.4 `public/get-trades`  ⬜

| Параметр | Тип | Обяз. | Дефолт |
|---|---|---|---|
| `instrument_name` | string | **да** | — |
| `count` | number | нет | 25 |
| `start_ts` / `end_ts` | number (мс) | нет | сутки назад / сейчас |

Ответ: `p` цена, `q` количество, `s` сторона (`BUY`/`SELL`), `i` инструмент, `t` время (мс),
`d` id сделки.

Чего это даёт, чего сегодня нет: **независимой проверки тейкер-флоу и объёма**. Сторона проставлена
биржей, а не выведена нами по правилу «сделка у аска = покупка» — то есть это оракул не только для
цены, но и для нашей агрегации ордерфлоу (`engine/`).

### 4.5 `public/get-tickers`

Единственный параметр — `instrument_name` (**необязательный**: без него приходят ВСЕ инструменты
одним ответом).

| Поле | Смысл |
|---|---|
| `i` | имя инструмента |
| `a` | **цена последней сделки** — то, с чем скилл сверяет `resolve_price` |
| `b` | лучший бид |
| `k` | лучший аск |
| `h` / `l` | максимум / минимум за 24ч |
| `c` | изменение цены за 24ч |
| `v` | объём за 24ч (в базовой) |
| `vv` | объём за 24ч в USD |
| `oi` | **открытый интерес** |
| `t` | штамп времени, мс |

⚠️ Однобуквенные имена — мина под I-6. `a` (last) и `b` (bid) отличаются одной буквой и оба
правдоподобны; перепутав, получим тихое смещение на полспреда, которое ни один гейт не поймает.

⚠️ Вызов без `instrument_name` возвращает всю биржу одним ответом — **дешёвый способ снять
эталон по десяткам символов за один запрос** вместо N запросов по одному.

### 4.6 `public/get-valuations` — mark / index / фандинг

| Параметр | Тип | Обяз. | Дефолт |
|---|---|---|---|
| `instrument_name` | string | **да** | — |
| `valuation_type` | string | **да** | — |
| `count` | number | нет | 25 |
| `start_ts` / `end_ts` | number (мс) | нет | сутки/30 дней назад · сейчас |

| `valuation_type` | Что | Темп | Статус |
|---|---|---|---|
| `index_price` | цена базового индекса | раз в минуту | ✅ MCP `get_index_price` |
| `mark_price` | маркировочная цена | раз в минуту | ✅ MCP `get_mark_price` |
| `funding_hist` | **фактически рассчитанный** фандинг | ежечасно | ⬜ НЕ ПОДКЛЮЧЕНО |
| `funding_rate` | текущая фиксированная ставка часа | раз в минуту | ⬜ НЕ ПОДКЛЮЧЕНО |
| `estimated_funding_rate` | оценка ставки СЛЕДУЮЩЕГО интервала | раз в минуту | ⬜ НЕ ПОДКЛЮЧЕНО |

Ответ: `instrument_name` + `data[]` с `v` (значение, строка) и `t` (время, мс).

⚠️ **`instrument_name` здесь у index-типа — ИНОЙ инструмент.** Пример из документации:
`BTCUSD-INDEX`, не `BTCUSD-PERP`. Подставив перп туда, где ожидается индекс, получим ошибку или
пустоту — снова через `get-instruments`, не угадывая.

⚠️ **Фандинг-окно Crypto.com — ЧАСОВОЕ**, у Binance USDⓈ-M — 8-часовое (у части символов 4ч).
Складывать или сравнивать «ставку» напрямую нельзя: это разные величины с разным знаменателем.
Скилл ровно об этом и предупреждает («у бирж разное фандинг-окно»); здесь это записано числом.

### 4.7 `public/get-insurance`  ⬜

`instrument_name` (валюта, напр. `USD`), `count` (25), `start_ts`/`end_ts`. Ответ: `v` (баланс
фонда), `t` (мс). Ценность — режимный контекст: просадка страхового фонда означает, что каскад
ликвидаций пробил маржу. Как фактор не подключён и обоснования (замера, I-7) под него нет.

### 4.8 `public/get-risk-parameters`  ⬜

Параметров нет. Отдаёт параметры риска площадки — из документированных полей:
`default_max_product_leverage_for_spot` (напр. `"1.0"`), `..._for_perps` (`"20.0"`),
`..._for_futures` (`"20.0"`), плюс таблицы дисконтов обеспечения и лимитов по валютам.
Полный состав полей на онлайн-странице раскрыт частично — **при подключении вычитывать
фактический ответ, а не этот абзац**.

### 4.9 `public/get-announcements`  ⬜

⚠️ **Живёт на ДРУГОМ корне**: `https://api.crypto.com/v1/public/get-announcements`, а не под
`/exchange/v1/`. В `ccxt` это отдельная секция `api['base']`.

| Параметр | Смысл |
|---|---|
| `category` | напр. `system` |
| `product_type` | `Spot`, `Derivative`, `Margin`, `Staking`, `Transfer`, … (список через запятую) |

Поля ответа: `id`, `category`, `product_type`, `announced_at`, `title`, `content`,
`instrument_name`, `impacted_params` (объект с `spot_trading_impacted`,
`derivative_trading_impacted`, `margin_trading_impacted`, `otc_trading_impacted`,
`convert_impacted`, `staking_impacted` — значения вида `PARTIAL` / `BAU`).

Почему это не мусор: при расхождении оракула с нашими числами первый вопрос — «а не были ли у
оракула техработы/приостановка». Здесь на него есть машиночитаемый ответ. Это ровно та подмена
«молчание источника ↔ смерть источника», на которой проект уже обжигался (`!forceOrder@arr`,
85.7% строк).

## 5. Публичные WebSocket-каналы

Подключение: `wss://stream.crypto.com/exchange/v1/market`. Аутентификация для публичных каналов
**не требуется**.

Подписка (проверено по `ccxt/pro/cryptocom.py::watch_public_multiple`):

```json
{ "method": "subscribe", "params": { "channels": ["ticker.BTCUSD-PERP"] }, "nonce": 1753900000000 }
```

**Heartbeat.** Сервер шлёт `{"id": …, "method": "public/heartbeat", "code": 0}`; клиент ОБЯЗАН
ответить `{"id": <тот же id>, "method": "public/respond-heartbeat"}`. Не ответив — получим разрыв,
который снаружи выглядит как «данные протухли». Это тот самый класс, что в `engine/`
разграничен как `received_ms` vs `event_ms`: молчание канала и смерть сокета — разные вещи.

| Канал | Пример | Статус | Что даёт |
|---|---|---|---|
| `book.{instrument_name}` | `book.BTCUSD-PERP` | ⬜ | полный снимок стакана |
| `book.{instrument_name}.{depth}` | `book.BTCUSD-PERP.10` | ⬜ | ограниченная глубина (10 / 25 / 50) |
| `ticker.{instrument_name}` | `ticker.BTCUSD-PERP` | ⬜ | 24ч-тикер + bid/ask + OI, поля как в §4.5 |
| `trade.{instrument_name}` | `trade.BTCUSD-PERP` | ⬜ | сделки в реальном времени со стороной |
| `candlestick.{timeframe}.{instrument_name}` | `candlestick.M5.BTCUSD-PERP` | ⬜ | OHLCV потоком |
| `index.{instrument_name}` | `index.BTCUSD-INDEX` | ⬜ | индексная цена |
| `mark.{instrument_name}` | `mark.BTCUSD-PERP` | ⬜ | маркировочная цена |
| `settlement.{instrument_name}` | `settlement.BTCUSD-210528` | ➖ только срочные фьючерсы | события расчёта |
| `funding.{instrument_name}` | `funding.BTCUSD-PERP` | ⬜ | часовая ставка фандинга |
| `estimatedfunding.{instrument_name}` | `estimatedfunding.BTCUSD-PERP` | ⬜ | оценка ставки следующего интервала |
| `user.*` | — | ➖ **ИСКЛЮЧЕНО**: требует аккаунт | — |

Документированный лимит WS-запросов — **100 запросов/с** (по подписке/методу).

### Дельта-режим стакана

Параметры подписки на `book` (подтверждены по `ccxt/pro/cryptocom.py`):

| Параметр | Значения | Смысл |
|---|---|---|
| `bookSubscriptionType` | `SNAPSHOT` (дефолт биржи) · `SNAPSHOT_AND_UPDATE` | полные снимки против дельт |
| `bookUpdateFrequency` | `100` мс для `SNAPSHOT` · `10` мс для дельт | темп обновления |

⚠️ ccxt по умолчанию просит `SNAPSHOT_AND_UPDATE`, тогда как биржа без параметра отдаёт
`SNAPSHOT`. То есть **поведение через ccxt и через сырой сокет различается по умолчанию** —
и дельта-поток требует поддерживать книгу самому (ccxt это делает, включая чексуммы).

## 6. Путь через CCXT — альтернатива MCP

`ccxt 4.5.68` поддерживает `cryptocom` и в REST, и в `ccxt.pro`. Это значит: **оракул достижим
из кода, а не только из MCP-диалога**, — но с оговоркой, которая рушит половину смысла.

Unified-методы, покрывающие публичную поверхность (`ccxt.cryptocom().has`, только `True`):

| Unified | Под капотом | Комментарий |
|---|---|---|
| `fetchMarkets` | `public/get-instruments` | `market['id']` = имя инструмента Crypto.com |
| `fetchCurrencies` | — | справочник валют |
| `fetchTicker` / `fetchTickers` | `public/get-tickers` | |
| `fetchOHLCV` | `public/get-candlestick` | ⚠ карта таймфреймов расходится с enum (см. §3) |
| `fetchOrderBook` / `fetchL2OrderBook` | `public/get-book` | |
| `fetchTrades` | `public/get-trades` | |
| `fetchFundingRate` / `fetchFundingRateHistory` | `public/get-valuations` | часовое окно! |
| `fetchSettlementHistory` | `public/get-expired-settlement-price` | |
| `sandbox: True` | `uat-api.3ona.co` | UAT-контур доступен |

`ccxt.pro.cryptocom()`: `watchTicker`, `watchTickers`, `watchBidsAsks`, `watchTrades`,
`watchTradesForSymbols`, `watchOHLCV`, `watchOrderBook`, `watchOrderBookForSymbols`.

⚠️ **Главная оговорка: CCXT-путь ослабляет оракул ровно в том, ради чего он существует.**
Скилл говорит прямо — ценность в том, что это «не CCXT». Пойдя к Crypto.com через ccxt, мы
оставляем биржу независимой, но **общий слой парсинга/нормализации CCXT — тот же самый**. Баг в
ccxt (или в нашем использовании ccxt) станет одинаковым с обеих сторон и взаимно погасится.
Практический вывод: **сверку цен/кадров/стакана держать на MCP-пути** (сырой HTTP оракула), а
ccxt-путь использовать только там, где нужен объём данных, недостижимый вручную, — и помнить,
что он проверяет уже не транспорт, а нашу логику поверх него.

## 7. MCP-путь (то, чем пользуется `/live-verify` сегодня)

Инструменты, наблюдавшиеся в сессии 2026-07-31: `get_instruments`, `get_instrument`, `get_book`,
`get_candlestick`, `get_ticker`, `get_tickers`, `get_trades`, `get_mark_price`, `get_index_price`.
Соответствие REST-методам — по §4; параметры и единицы те же.

⚠️ **Инструкция MCP-сервера расходится с фактически выставленным набором инструментов.** Сервер

`get_trades` / `get_candlestick` с именами вида `BTCUSD-PERP`. Наблюдение, не приговор — но
**имя символа из самоописи (`BTC_USDT`, спотовый формат) подставлять в реальные инструменты
нельзя**: это ровно та подстановка «правдоподобного, но чужого», от которой предостерегает скилл.
Сверять через `get_instruments`.

## Что не подключено

**Ничего из Crypto.com не подключено к коду вообще** — grep по `hunt_core/` (2026-07-31) даёт
ноль совпадений. Оракул целиком живёт в MCP-диалоге по скиллу `/live-verify`. Ниже —
публичные поверхности, не используемые даже там.

| Поверхность | Что даёт | Почему это стоит внимания |
|---|---|---|
| `public/get-trades` ⬜ | лента сделок со **стороной от биржи** | единственный способ проверить нашу агрегацию ордерфлоу чужой разметкой, а не нашим же правилом |
| `get-valuations: funding_hist / funding_rate / estimated_funding_rate` ⬜ | фандинг тремя срезами | у нас кросс-венью фандинг считает `engine/multi.py` по OKX/Bybit/Bitget — **все через ccxt**; Crypto.com дал бы точку вне ccxt. ⚠ окно часовое, не 8ч |
| WS `mark` / `index` / `funding` / `estimatedfunding` ⬜ | пуш вместо опроса | сверка **свежести планов** (`plane_ages`) требует пуш-темпа, а не REST-снимка |
| WS `book` с `SNAPSHOT_AND_UPDATE` ⬜ | дельта-книга 10 мс | наши стены и `imb_*` живут на пуш-книге; сверять пуш снимком REST — сравнивать разные вещи |
| WS `trade` / `ticker` / `candlestick` ⬜ | потоковые аналоги REST | закрытие бара на чужом сокете — независимый свидетель против I-5 |
| `public/get-insurance` ⬜ | страховой фонд | режимный прокси стресса деривативов |
| `public/get-risk-parameters` ⬜ | плечи и дисконты площадки | контекст, не сигнал |
| `public/get-announcements` ⬜ | делистинги, техработы, приостановки | **отличает «молчание источника» от «поломки»** при разборе расхождений |
| `public/get-expired-settlement-price` ➖ | расчёт истёкших фьючерсов | у нас только перпы |
| `public/staking/get-conversion-rate` ➖ | ликвид-стейкинг | к сигналам отношения не имеет |
| `public/auth`, всё `private/*`, WS `user.*` ➖ | — | **ИСКЛЮЧЕНО**: требуют ключ/подпись/аккаунт — вне scope этого справочника и вне scope проекта (ордеров/балансов здесь нет by design) |

⚠️ Ни одно «⬜» **не является задачей**. Инвариант I-7 требует замера прежде включения: окно и
источник без обоснования — магическое число. Список — опись доступного, не бэклог.
