## 1. Что это и где граница области

Перенос онлайн-документации бирж в офлайн — **включая то, чего в проекте нет**, потому что
«нет» и «не нужно» это разные вещи, и различить их можно только имея опись. Каждый эндпойнт,
поток и ccxt-метод помечен одним из трёх маркеров:

| | значение |
|---|---|
| ✅ **ИСПОЛЬЗУЕТСЯ** | + call site в `hunt_core/` |
| ⬜ **НЕ ПОДКЛЮЧЕНО** | + что бы дало |
| ➖ **не нужно / EXCLUDED** | + почему |

**Жёсткая граница области.** Каталог документирует **только публичные поверхности**: ни ключа,
ни подписи, ни `listenKey`, ни контекста аккаунта. Ничего про ордера и торговлю, балансы,
позиции, плечо/маржу, вводы/выводы/переводы, суб-аккаунты, управление ключами, user data streams.
Публичная, но **околоторговая рыночная статистика** (ликвидации, открытый интерес, фандинг,
long/short ratio, implied volatility) — **в области**. Эндпойнты, требующие ключа, перечислены
в каждом файле **один раз** строкой EXCLUDED и не раскрываются: подробная строка со
спецификацией читалась бы как «можно брать».

⚠️ **Префикс пути не является доказательством публичности — это измерено, а не предположено.**
Ревизия 2026-08-01 нашла три случая, где имя врало в обе стороны:

| поверхность | что говорило имя | что ответил живой запрос без ключа |
|---|---|---|
| OKX `GET /api/v5/public/economic-calendar` | префикс `/public/` | **HTTP 401** `{"code":"50103","msg":"Request header OK-ACCESS-KEY can not be empty."}` → переведён в EXCLUDED |
| Binance `fapiPublicGetApiTradingStatus`, `/fapi/v1/historicalTrades` | namespace `fapiPublic` | **HTTP 401** `{"code":-2014}` → оба EXCLUDED |
| Binance SPOT `/api/v3/historicalBlockTrades` | стоял EXCLUDED «требует `X-MBX-APIKEY`» | **HTTP 200 с данными** без ключа → ярлык снят, эндпойнт публичный |

### Чем это НЕ является

**Это перенос документации, а не замер.** Часть чисел перепроверена живыми запросами
(веса Binance, cost'ы ccxt, формы ответов, маршруты WS) — это отмечено в шапке каждого
ревизованного файла. Остальное — цитата страницы, и цитата в этом проекте доказательством
не считается ([`CLAUDE.md`](../../../CLAUDE.md), директива владельца 2026-07-25: «проверять на
живых данных или прогоном бота с разбором его логов»).

**Ни одно ⬜ в этом каталоге не является задачей.** Инвариант I-7: окно или источник без
замера — магическое число. Прежде чем что-либо отсюда включать, надо доказать A/B на живом
снимке, что оно вообще меняет решение. Список — опись доступного, не бэклог.

**Маркеры ✅/⬜ — снимок графа вызовов на 2026-07-31/08-01, и они гниют.** Правило доказательства
маркера ✅ — **настоящий вызов** (`ex.<method>(`, `fapiPublicGet<X>(`, `await rest.<fn>(`).
Имя в докстроке маркером не является: в этом репозитории докстроки штатно переживают удалённый
код. Ревизия сняла по этому правилу **8 ложных ✅** — пять в `binance-usdm-rest.md`, три в
`binance-futures-data-stats.md`; все они цитировали `contract.py` (словарь строк для
ops-сообщений), `engine/params.py` (комментарий), `features/prepare_frame.py` и
`toolkit/ohlcv.py` (докстроки).

⚠ **Проверка идёт в обе стороны, и это не симметричная мелочь.** Два ⬜ оказались вызываемыми
**каждый тик** — Bybit `/v5/market/orderbook` и Bitget `merge-depth` (оба через
`engine/multi.py::cross_orderbook` → `maps/cross.py::aggregate_cross_walls`), а вместе с ними
пришлось снять две прозаические строки, утверждавшие «стены считаются только по первичной» и
«стакан читается только с Binance». Ложное ⬜ опаснее ложного ✅: оно предлагает «подключить»
то, что уже работает, и прячет реальную стоимость обхода.

⚠️ **Примечание к строке про ликвидации Bitget — снято при проверке 2026-08-01.**

а отсутствует только его реализация в ccxt, и что докстрока `engine/multi.py::cross_liquidations`

* **Публичного канала ликвидаций в доках Bitget найти не удалось.** В публичных WS-каналах

  встречаются в приватных (ADL, позиции) и в маржинальных/earn REST-эндпойнтах, требующих ключа.

Итого: **факт не подтверждён ни в одну сторону.** Замер `has['watchLiquidations'] = None` у
bitget верен, но он говорит только про ccxt. Пока прямая подписка на канал не проверена живьём,
докстрока `multi.py` остаётся в силе, а строка выше не является задачей. Правило то же, что для
всего каталога: **неподтверждённое не выдаём за факт** — именно так рождаются документы,
описывающие желаемое как существующее.

### Осознанно ➖ — не подключать (причина измерена, а не эстетическая)

- **Все `!…@arr` «вся биржа одним потоком»** на фьючерсах: у `!bookTicker` один кадр = один
  символ (замер 2026-07-26: **1.4%** полезных кадров, медиана **5.0 с** против 0.005 с со
  списком — ×1000); у `!markPrice@arr` кадр — массив на 441 символ при **0.79%** полезных,
  то есть ~850 лишних парсов/с в том же event loop, где считаются Polars-фичи.
- **`uiKlines`** — бары «для отрисовки», совпадение с `klines` не гарантировано.
- **SBE** — ccxt не поддерживает; потребовал бы собственного транспорта ради вторичной венью.
- **Bybit `liquidation.{symbol}`** (deprecated) — ≤1 ордер в секунду, пропускает большую часть
  каскада; вытеснен `allLiquidation`.
- **`fetch_liquidations` (REST)** — публичного REST-эндпойнта ликвидаций **нет ни у одной**
  из четырёх площадок. История ликвидаций может быть только накоплена своим слушателем.
- **Спот-контур Bitget, legacy `/api/mix/v1/`, тестнет/демо-хосты, `fetchCurrencies`,
  `*Ws`-варианты REST-методов, `fetchSettlementHistory`** (у бессрочных нет экспирации).

## 4. Что этот набор НЕ покрывает

**Всё, что требует ключа.** По построению и намеренно. В каждом файле такие поверхности
перечислены **одной строкой** и не раскрыты: ордера и торговля, балансы, позиции, плечо и
маржа, вводы/выводы/переводы, суб-аккаунты, управление ключами, user data streams
(`listenKey`), namespace'ы `sapi*` / `papi*` / `fapiPrivate*` / `eapiPrivate` / `dapiPrivate*`,
приватные WS-топики. Механически это же запрещено в коде:
[`docs/ai/rules/prohibited-apis.md`](../../ai/rules/prohibited-apis.md) + `scripts/check_prohibited_apis.py`
в pre-commit + хук `scripts/guard_edit.py` до записи в файл.

**Площадки вне набора.** Покрыты Binance (USDⓈ-M / spot / COIN-M / options / архивы), OKX,
Bybit, Bitget, CoinGecko, Crypto.com. **Нет:** Deribit (главный опционный рынок и эталон IV —
пробел заметный, если опционы вообще пойдут в дело), Coinbase / Kraken (а они входят в корзины
индексов Binance с весом 0.13 каждый), Hyperliquid и прочие on-chain перпы, Coinglass и
агрегаторы ликвидаций, любые DEX.

**Классы данных вне набора.** On-chain, стаканы уровня L3, соцданные и новости, макро-календарь
(единственный найденный канал — OKX `economic-calendar` — оказался за ключом), спотовые данные
вторичных площадок (спот берётся только с Binance).

**Утверждения, которые авторы пометили как НЕПРОВЕРЕННЫЕ или противоречивые** — их нельзя
цитировать как факт:

| что | в чём противоречие | как закрыть |
|---|---|---|
| Веса Binance без символа | `premiumIndex` док 10 / ccxt 1 · `constituents` док 2 / замер 1 · `insuranceBalance` док 1 / замер **40** · `indexInfo` док 1 / замер 10 · futures `bookTicker` док «2 или 4» | Мерить по `X-MBX-USED-WEIGHT-1M` перед каждым массовым опросом. Сторона нигде не выбрана намеренно |
| Регистр `adlRisk` | страница пишет `low`, живой ответ отдал **`"LOW"`** | Сравнивать регистронезависимо; `== "low"` не сработает никогда |
| CoinGecko: время вчерашней дневной точки | страница `/market_chart` — **00:10 UTC**, страница `/market_chart/range` — **00:35 UTC** | Обе стороны записаны с атрибуцией; победитель не выбран |
| CoinGecko: keyless-лимит | 5–15 calls/min; Demo 30 vs 100 | Статья поддержки отдаёт **HTTP 403** машинному запросу — сторона больше не переверяема |
| Bybit: точные публичные REST-лимиты | страница `v5/rate-limit` в этом заходе не выгружена | Число **намеренно не подставлено** (I-7) — «разумное значение» здесь не считается |
| Архив `metrics`: шаг ряда | расчёт по размеру zip даёт 5 мин, issue #211 говорит «раз в сутки» | Только распаковкой первого файла. На этом шаге стоит вся ресемплировка OI |
| Binance Options: WS-эндпойнт | `nbstream` vs `fstream` — расхождение не закрыто | Вскрыть оба сокета и записать, какой шлёт кадры |
| Bitget: вся документация | `bitget.com/api-doc/*` — **JS-SPA**: машинный запрос отдаёт UTA-интро вместо таблицы параметров; `wiki/bitget-api-rate-limits` отдаёт **404** | Поля и лимиты сняты **живыми вызовами** публичного API, а не цитатой. Оставшиеся ссылки помечены как «индексируются, открываются вручную» |
| Bitget `merge-depth` `precision`/`scale0…5` | биржевая кластеризация уровней со своей не сравнивалась | Сравнить на одном снимке — `maps/` делает ту же работу сам |

**Наконец — сам каталог не имеет механического гарда.** Ни один гейт проекта (ruff, mypy,
vulture, `check_structure.py`) о содержимом `docs/` ничего не знает. Маркеры ✅/⬜ проверялись
грепом вручную; разовый чекер маркеров (жил во временном каталоге сессии, **в репозиторий не
вносился**) прогонялся по 10 файлам из 15 и дал **1 настоящий дефект из 18 кандидатов** — то
есть 94% его срабатываний были шумом, и заменой ручной сверки он не является. Каталог начнёт
гнить с первого коммита в `hunt_core/`, как и весь `docs/`.
