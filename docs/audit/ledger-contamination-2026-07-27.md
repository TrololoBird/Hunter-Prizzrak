# Леджер был на 86% тестовыми фикстурами — 2026-07-27

**Статус: ЗАКРЫТО.** Утечка запечатана, файл вычищен, все процитированные ранее числа
пересчитаны.

## Что нашлось

Правка началась как «починить сумму pnl: размер позиции, комиссии, перекрытия». Первый же
замер входных данных показал, что чинить арифметику рано.

В `data/signal_history.jsonl` было **3722 строки. 3423 из них — тестовые фикстуры.**

| | строк | сумма `pnl_pct` | винрейт |
|---|---|---|---|
| фикстуры | 3423 (92%) | **+41414%** | 90.9% |
| настоящие сделки | 299 (8%) | +1630% | **47.6%** |

Две фикстуры, обе узнаются по буквальному повтору геометрии:

* **3175 строк по символу `X`** — вход 100, стоп 90, цели 110 и 150;
* **248 строк ETHUSDT** — вход 99/100, выход 116.5, длительность ровно 60.0 мин; 247 из них
  побайтово одинаковы.

## Как они туда попадали

У `tracker.close_signal` параметр `archive` имеет значение по умолчанию **`True`**, а его
докстрока просила тесты передавать `archive=False`. Прямые вызовы из тестов так и делали —
и потому выглядело, будто дисциплина соблюдена.

Но `close_signal` зовут **изнутри ещё 17 мест** (`auto_resolve_active_signals`,
`_evaluate_levels`, `_followups`), и туда аргумент не передаётся. Любой тест, дёргающий
функцию уровнем выше, писал в боевой файл через дефолт.

Проверено счётчиком строк, а не чтением кода:

```
uv run pytest tests/test_manipulation_runner.py   →  +9 строк в боевом леджере
```

Темп накопления: 372 строки за 2026-07-26, 198 за 07-27. Утечка была активной.

**Урок.** «Тесты передают `archive=False`» — это обещание, а не механизм. Обещание молча не
исполнялось больше месяца, и заметить это по коду было нельзя: каждый отдельный тест выглядел
правильным. Заметил только замер самих данных.

## Чем закрыто

1. **`tests/conftest.py`** — autouse-фикстура уводит `SIGNAL_HISTORY`, `SIGNAL_EVENTS`,
   `SIGNAL_STATE` в `tmp_path`. Новый тест изолирован по умолчанию; помнить не нужно.
2. **`outcomes.py::_refuse_production_write`** — приёмник падает, если запись в боевой
   каталог всё-таки началась. Боевой каталог вычисляется **от файла модуля**, а не из
   `paths.DATA`: первая редакция читала `paths.DATA` — который фикстура и подменяет — и
   объявила боевым сам песочный каталог, уронив 9 честных тестов.
3. **`tracker.py`** — широкий `except Exception` вокруг записи больше не глушит этот отказ.
   Именно он превращал утечку в тихую.
4. **`scripts/purge_fixture_rows.py`** — фикстуры переехали в
   `data/signal_history.fixtures-2026-07-27.jsonl`. Не удалены: если критерий окажется
   неверным, откат — склейка двух файлов.
5. **`tests/test_ledger_not_polluted_by_tests.py`** — 5 гардов, включая проверку, что в
   боевом файле не осталось повторяющейся геометрии.

Критерий фикстуры — **повтор ключа** (символ, обе кромки входа, стоп, обе цели, выход,
длительность) пять и более раз. У настоящей сделки цены приходят с биржи `float`-ами, а
длительность меряется в момент закрытия; рынок такого повтора не порождает. Критерий
намеренно уже, чем `is_polluted` (тот считает мусором любую строку без `score`/`fuel` — их на
16 больше): чистить боевой файл по косвенному признаку нельзя.

## Что пришлось переписать в уже сделанных выводах

Все числа, названные мной ранее по этому файлу, были посчитаны по данным, где 92% строк —
фикстуры. Сами дефекты подтверждены независимо и остаются настоящими; неверен был **масштаб**.

| утверждение | было названо | на самом деле |
|---|---|---|
| винрейт по разрешённым | 87.6% | **47.6%** (91W / 100L) |
| размер выборки | 3659 | **283** |
| доля `timeout` | 28% (1020 сделок) | **8.8%** (25 сделок) |
| доля `unresolved` | 29.8% | **32.2%** (91 из 283) |
| вырожденных зон входа | 88.5% | **40.6%** |
| медиана ширины зоны | 1.010% | **2.245%** |
| сумма pnl | +41105% | +1575% — и она всё равно ничего не значит |

Два уточнения по направлению ошибки:

* **Винрейт был завышен фикстурами**, а не занижен: их собственный винрейт 90.9% — они
  победы почти поголовно, потому что фикстура пишется под проверяемый сценарий.
* **Дефект базы PnL оказался КРУПНЕЕ заявленного.** Фикстуры имели `entry_lo == entry_hi` по
  построению и раздували долю вырожденных зон. На настоящих данных зона не вырождена у 59%
  сделок, а медианная ширина вдвое больше — значит расхождение баз затрагивало больше сделок,
  чем я утверждал.

## Почему это не поймали раньше

`is_polluted` (нет `opened_at` / `score` / `fuel`) исключал эти строки из `/stats` — то есть
Telegram-отчёт показывал их не полностью. Но **сырой файл читают не только через `/stats`**:
любой разовый замер, любой скрипт анализа, любая моя собственная проверка шли по файлу
напрямую и получали 92% мусора. Фильтр на одном из читателей не заменяет чистых данных.

Механических гардов на содержимое `data/` не было вовсе — `pytest --cov`, `ruff`, `vulture`
и `mypy` про данные ничего не знают, а тесты, как выяснилось, сами и были источником.
