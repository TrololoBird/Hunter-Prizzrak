## ⚠ Границы того, что доказано

Записано отдельно, потому что «сделано» и «доказано» — разные утверждения.

1. **Охват BLE001 не доказан (T2.4).** Что правило включено для `features`/`prizrak` —
   доказано (`ruff --show-settings`). Что оно поймает будущий регресс — НЕТ: воспроизвести
   срабатывание на искусственном `except Exception: return None` не удалось, ruff 0.15.22
   на этой форме молчит. Шесть молчаливых мест закрыты по существу, независимо от линтера.
   Это тот же класс, что зафиксирован в CLAUDE.md про S110/S112.

2. **Копия старой схемы ≠ оригинал (T4.1).** Дифф «3 символа сменили сторону» снят против
   воспроизведённой копии, которая не повторяет половинную скидку веса для BOS-only тренда.
   Расхождение с базовой линией — один символ, то есть настоящее число 2–4.

3. **Соответствие методологии ≠ доходность.** Ни один критерий T4.1 не про прибыль:
   бэктеста в проекте нет, корпус разборов — 11 файлов / 123 уровня. Два потерянных
   символа (SUPER, THETA) — реальная цена решения «1W не задаёт сторону», и проверить её
   можно только накоплением исходов в леджере.

4. **Смоук-импорт — нижняя граница.** Он не исполняет отложенные импорты внутри функций
   (их в дереве 204), а живой прогон в CI проверяет старт, а не цикл.

## Закономерность, которую стоит держать в виду

**Числа ТЗ и прежних аудитов расходились с живым замером чаще, чем совпадали.** Не
единичный случай, а восемь из восьми проверенных:

| утверждение | оказалось |
|---|---|
| cp314-колёс у polars нет → блокер | колёса `cp310-abi3`, вопроса не существует |
| ATR-хвост после дыры должен стать null | null только на дыре, дальше корректный пересчёт |
| `engine/health.py` — «не трогать, это аптайм» | связан с ingest-штампами, требовал правки |
| XAU/XAG: фандинг 8ч, cap ±0.05% | 4ч, cap ±0.5% |
| `saw`: 0 срабатываний → детектор мёртв | порог достижим в 27.31% окон, реализация верна |
| `bos_max_bar_offset`: «не фильтрует» | фильтрует НАОБОРОТ (falsy-zero на offset=0) |
| `max_lookback`: «не срабатывает» | режет 31.6% строк, просто в невидимом месте |
| H&S: «плохой lookback» | модуль не исполняется вовсе |

Практический вывод для оставшихся 17 задач: **исходное утверждение проверяется до того,
как на нём что-то строят.** Дешевле всего это делать замером достижимости («может ли
условие сработать в принципе»), а не частоты («сколько раз сработало»).
