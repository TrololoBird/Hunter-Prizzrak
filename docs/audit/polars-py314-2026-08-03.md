# polars на Python 3.14 — колесо есть, вопрос закрыт

**Статус:** АКТУАЛЬНО · сверено с деревом **2026-08-03**
**Задача:** T0.1 из `IMPLEMENTATION_SPEC_Hunter-Prizzrak.md` (помечена БЛОКЕР)
**Вердикт:** `requires-python = ">=3.14,<3.15"` **остаётся**. Код не меняется.

## Что утверждало ТЗ

> Наличие официальных cp314-wheels для polars 1.43.x внешне подтвердить не удалось
> (issue pola-rs/polars #25035 открыт; официально заявлена поддержка 3.9–3.13).

## Почему подтвердить не удалось — и почему это не блокер

Искали не тот дистрибутив. **С разделения рантайма пакет `polars` на PyPI — чистый
Python-шим**, у него вообще нет платформенных колёс:

```
polars-1.43.2-py3-none-any.whl
polars-1.43.2.tar.gz
```

Скомпилированная часть уехала в отдельный дистрибутив `polars-runtime-32`
(и `polars-runtime-64` для bigidx), и там колёса такие (замер 2026-08-03, PyPI simple API):

```
polars_runtime_32-1.43.2-cp310-abi3-win_amd64.whl
polars_runtime_32-1.43.2-cp310-abi3-manylinux_2_17_x86_64.manylinux2014_x86_64.whl
polars_runtime_32-1.43.2-cp310-abi3-macosx_11_0_arm64.whl
… (8 колёс, все cp310-abi3)
```

**`cp310-abi3` — стабильный ABI.** Такое колесо подходит любому CPython ≥ 3.10, включая
3.14, и отдельного `cp314`-колеса для этого не требуется по построению. Поиск подстроки
`cp314` даёт ноль совпадений и будет давать его всегда — это не признак отсутствия
поддержки, а признак того, что искали не ту схему тегов.

## Замер (то, чего требовало ТЗ дословно)

Чистое окружение, `uv venv --python 3.14`:

```
Using CPython 3.14.6
Resolved 2 packages
 + polars==1.43.2
 + polars-runtime-32==1.43.2
```

Исполнение, а не только импорт:

```
python 3.14.6
polars 1.43.2
12          ← pl.DataFrame({'a':[1,2,3]}).with_columns(b=pl.col('a')*2) → sum(b)
```

Боевое окружение проекта (`.venv`, Python 3.14.6) несёт `polars 1.43.1` +
`polars-runtime-32 1.43.1` и работает — то есть факт подтверждён дважды, на чистом
окружении и на рабочем.

## Что из этого следует для сопровождения

⚠ **`polars-runtime-32` — отдельный дистрибутив, и он невидим в `pyproject.toml`.**
Пол `polars>=1.43.1` управляет шимом; рантайм тянется транзитивно и на него не заведено
ни пола, ни потолка. Проверять версию рантайма надо явно (`uv pip list | grep polars`),
а не через версию `polars`: расхождение между ними — это тот же класс «зелёный гейт на
неизмеренном объекте», который уже описан в `pyproject.toml` про пол ccxt.

⚠ **Про NumPy** ТЗ право: 2.4.6 стоит и поддерживает 3.14. Потолок `<2.5` в
`pyproject.toml` держится не из-за Python, а из-за numba (транзитивно через `polars-ta`).
